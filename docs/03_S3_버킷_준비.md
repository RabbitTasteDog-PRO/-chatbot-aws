# 대화 저장 버킷 유지와 React 배포 버킷 생성

## 1. 기존 대화 저장 버킷 확인

**S3 → 범용 버킷 → 2일차에 만든 본인 버킷** 열기. 버킷 이름을 기록하고 **권한 → 퍼블릭 액세스 차단**이 모두 켜져 있는지 확인.

새 챗봇은 로그인한 사용자의 대화를 TXT로 내보내는 기능을 포함. EC2의 Django가 `day2/chat-exports/` 아래에 파일을 저장하고 최대 10분 유효한 다운로드 URL을 반환함. 기존 `hello.txt` 실습과 같은 S3를 실제 앱에서 사용하게 됨.

| 버킷 | 저장 내용 | 파일을 읽는 주체 |
| --- | --- | --- |
| 기존 버킷 | 개인 대화 TXT | EC2 역할로 만든 임시 다운로드 URL 사용자 |
| 새 프론트 버킷 | React HTML·JS·CSS | CloudFront OAC |

대화 TXT 버킷에 CloudFront 공개 제공용 정책을 붙이지 않음. 버킷을 구분하면 프론트 배포 작업이 대화 파일을 삭제하거나 공개하는 것을 피할 수 있음.

## 2. React 버킷 생성

**S3 → 범용 버킷 → 버킷 만들기**를 열고 다음 값 입력.

| 항목 | 선택·입력값 |
| --- | --- |
| 리전 | 아시아 태평양(서울) · `ap-northeast-2` |
| 버킷 유형 | 범용 |
| 이름 공간 | 공유 글로벌 이름 공간 항목이 있으면 선택 |
| 버킷 이름 | `skn33-frontend-ALIAS-날짜-임의숫자` |
| 객체 소유권 | ACL 비활성화 / 버킷 소유자 적용 |
| 퍼블릭 액세스 차단 | **모두 유지** |
| 버킷 버전 관리 | 이번 실습에서는 비활성화 |
| 기본 암호화 | SSE-S3 |

**버킷 만들기** 클릭. 영문 소문자·숫자·하이픈 사용. 전역에서 중복되지 않아야 하므로 이름 충돌 시 마지막 숫자 변경.

**정적 웹 사이트 호스팅은 활성화하지 않음.** CloudFront에서 S3 REST 원본과 OAC를 사용해 비공개 버킷의 파일을 전달할 예정임. S3 웹 사이트 엔드포인트는 이 방식과 다름. [AWS OAC 안내](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-restricting-access-to-s3.html)

**확인 결과:** S3 버킷 목록에 기존 대화 버킷과 새 프론트 버킷이 구분되어 있음. 아래 이름을 다음 단계에 사용.

| 문서 자리표시자 | 실제 값 |
| --- | --- |
| `EXPORT_BUCKET` | 기존 대화 저장 버킷 이름 |
| `FRONTEND_BUCKET` | 새 React 배포 버킷 이름 |

## 3. EC2 역할에 대화 저장 권한 연결

**IAM → 역할 → 새 EC2에 연결한 역할 → 권한 → 권한 추가 → 인라인 정책 생성 → JSON** 선택. `EXPORT_BUCKET`을 기존 버킷 이름으로 변경.

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["s3:PutObject", "s3:GetObject"],
    "Resource": "arn:aws:s3:::EXPORT_BUCKET/day2/chat-exports/*"
  }]
}
```

다음 화면에서 이름 `ChatbotConversationExport` 입력 후 생성. 기존 역할이 동일 버킷의 `day2/*`에 이미 같은 권한을 가지고 있으면 중복 생성하지 않음.

**확인 결과:** 새 EC2 역할에 S3 저장·다운로드와 SSM 권한이 있음. ECR 읽기 권한은 다음 ECR 접근 권한 가이드에서 추가. S3용 EC2 인바운드 규칙은 필요 없음. EC2 HTTPS 아웃바운드는 유지.
