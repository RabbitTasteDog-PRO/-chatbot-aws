# 실습 파일과 계정 권한 준비

## 1. 새 프로젝트 준비

배포 자료의 `chatbot_aws.zip`을 내 PC에서 압축 해제. 새 폴더 `chatbot_aws`를 기존 `_chatbot_fullstack`과 구분. 실제 `.env`와 개인 키는 압축에 포함하지 않음.

| 폴더·파일 | 사용하는 단계 |
| --- | --- |
| `backend/` | Django 이미지 빌드 |
| `frontend/` | React 빌드 |
| `deploy/` | EC2 실행·S3 배포·자동 배포 검사 |
| `infra/` | IAM·OAC 정책 예시 |
| `compose.prod.yaml` | EC2 운영 컨테이너 |
| `.env.example` | EC2에서 복사·수정할 환경 예시 |
| `.github/workflows/` | GitHub Actions |

## 2. 사용할 권한 구분

학원 IAM 사용자에게 모든 작업 권한이 있는 것은 아님. 아래 자원을 생성·수정할 수 있는지 수업 전에 확인. 역할 생성·연결이 제한되어 있으면 계정 관리자가 준비.

| 사용하는 주체 | 필요한 작업 |
| --- | --- |
| 내 PC의 IAM 사용자 | 본인 ECR 이미지 업로드, 프론트 버킷 파일 업로드·CloudFront 무효화 |
| AWS 콘솔의 수업 사용자 | EC2·보안 그룹·RDS·S3·CloudFront 생성·수정, 허용된 IAM 역할 연결 |
| 새 EC2 역할 | ECR 이미지 다운로드, SSM, 기존 버킷의 대화 TXT PutObject·GetObject |
| GitHub OIDC 역할 | 해당 ECR 업로드, 프론트 버킷 배포, CloudFront 무효화, 해당 EC2 SSM 배포 |
| 도메인 확장 사용자 | ACM 요청·DNS 편집·ALB 생성 |

**새 EC2 생성 전에 연결할 역할부터 준비.** 기존 수업 역할을 재사용한다면 SSM 정책이 있는지 확인하고 생성은 생략.

1. **IAM → 역할 → 역할 생성 → 신뢰할 수 있는 엔터티 유형: AWS 서비스 → 사용 사례: EC2** 선택.
2. 권한에서 `AmazonSSMManagedInstanceCore` 검색·선택.
3. 이름 `skn33-day3-ec2-role-ALIAS`로 생성. 이 역할을 1단계 EC2 생성 화면의 IAM 인스턴스 프로파일에서 선택.
4. 역할 생성·연결 권한이 없으면 학원 관리자에게 해당 역할 준비·연결 요청.

이 시점에는 SSM 기본 역할만 준비. **3단계에서 기존 대화 S3 권한을 연결하고, 4단계 전에 [ECR 접근 권한](08_ECR_접근권한.md)을 읽어 ECR 저장소·로컬 업로드·EC2 다운로드 권한을 추가.** 같은 S3 권한이 이미 있으면 통합 정책에 중복 추가할 필요 없음. 프론트 버킷·CloudFront ID는 각각 생성 후 로컬 배포 정책의 해당 리소스에 반영.

GitHub OIDC는 수동 배포 성공 후 [GitHub OIDC·SSM](09_GitHub_OIDC_SSM.md)에서 연결. 정책 JSON의 대문자 자리표시자를 실제 값으로 바꾸며 `AdministratorAccess`로 우회하지 않음.

## 3. 내 PC 실행 환경

Mac은 터미널, Windows는 **WSL Ubuntu 터미널**에서 Bash 명령 실행. Docker Desktop의 Linux 컨테이너 실행과 WSL 통합 확인. Node.js 24 LTS·Git·AWS CLI v2 준비.

기관 IAM 사용자의 브라우저 로그인 방식은 AWS CLI **v2.32.0 이상**, `SignInLocalDevelopmentAccess` 권한이 필요함. 이 권한은 로그인 권한이며 ECR·S3 업로드 권한을 자동으로 주지 않음.

AWS CLI가 없으면 [ECR 접근 권한 가이드](08_ECR_접근권한.md)의 **내 PC의 Docker·AWS CLI 준비** 절에서 본인 OS 설치 부분만 먼저 진행. Mac은 macOS 설치, Windows는 WSL Ubuntu 안의 Linux 설치를 사용. 다른 터미널에 설치한 AWS 프로필이 자동 공유된다고 가정하지 않음.

**IAM → 사용자 → 본인 사용자 → 권한 → 권한 추가 → 직접 정책 연결**에서 `SignInLocalDevelopmentAccess`를 연결. 이미 사용자 또는 소속 그룹에 있으면 생략. 기관 계정에서 권한 추가가 막혀 있으면 관리자에게 요청. 아직 만들지 않은 ECR·프론트 버킷의 업로드 권한은 뒤에서 이름이 정해진 후 연결.

```bash
aws --version
aws configure set region ap-northeast-2 --profile skn33
aws login --profile skn33
aws sts get-caller-identity --profile skn33
```

브라우저에서 학원 계정의 본인 IAM 사용자로 로그인. 기존 기관 프로필이나 SSO 방식을 지정받았다면 해당 승인 방식을 사용하고 이후 명령의 프로필 이름도 맞춤. AWS 장기 액세스 키를 새로 만들어 앱에 넣지 않음.

**확인 결과:** STS의 Account가 수업 AWS 계정, Arn이 본인 인증 주체를 가리킴. EC2에 저장할 키가 아니며 내 PC CLI에서만 사용하는 로그인임. [AWS 로컬 개발 로그인](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-sign-in.html)

수업 중 사용할 리전은 서울이며 CloudFront 사용자 도메인 인증서만 버지니아 북부에서 생성. 7단계까지 진행하려면 도메인과 DNS 편집 권한도 미리 확보.
